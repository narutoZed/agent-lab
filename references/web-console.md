# 网页任务发布台

发布台新增网页发布、XLSX 导入和任务勾选。原有 `orchestrate.py serve` 仍为单实验只读看板；已生成的 `comparison/index.html` 仍为离线对比报告。

## 启动

需要 Python 3.10+；解析 XLSX 和网页服务仅使用标准库。底层桌面 CLI 仍需要 Node.js 22+，客户端应已登录并开启各自本机控制入口。当前桌面真机验证环境为 macOS；Windows 代码路径有兼容处理，未完成真机联调。

```text
python <skill>/scripts/task_console.py --root "批次保存目录" --port 18749
```

访问终端输出的 `http://127.0.0.1:18749/`。`--root` 保存全部批次、独立工作目录、回执、日志和任务状态；重启时沿用原目录即可看到历史。一个目录同一时刻只能运行一个控制台实例。关闭网页不会关闭服务；关闭服务后，已启动的原生任务可能继续，未发布队列在下次启动时暂停，需点击“继续队列”。

## 导入和选择任务

1. 下载页面中的 XLSX 模板，替换三条示例内容。表头包括任务编号、任务名称、任务正文、验收要求。
2. 导入 XLSX。上限 10 MB、2000 条任务、100 列、30 个非空工作表。旧版 XLS、加密文件、宏工作簿不支持；公式单元格请先复制并粘贴为值。
3. 选择工作表，核对列映射。首个非空行作为表头。支持任意列名的手动映射；只有任务正文必填，未填名称时截取正文作为名称。隐藏工作表有明确标记。
4. 搜索、逐条勾选或选择筛选结果。筛选不会取消其他已勾选任务；“清空勾选”清除全部选择。切换工作表或映射会重建清单并清空选择；重新导入会替换当前清单。
5. 可手动添加任务。每批最多选择 100 条。重复任务编号、空正文、映射到公式或错误值的行不能勾选；点击任务名称查看详情和错误原因。

导入仅在本机解析，文件不会上传到第三方平台。实际发布的是选中行的任务正文；不会把整本工作簿或其他附件发送给 Agent。

## 平台与模型

- Codex、WorkBuddy：模型输入框接受客户端支持的模型 ID，留空使用默认值。WorkBuddy 的参数传给原生新建会话接口；此版本没有可用模型目录，也没有强制匹配验证。进度页区分请求模型与日志模型，已观察到不一致时提示核验（也可能是模型别名）。
- 即先：可选择报告、创造、搜索、开发需求阶段；报告支持 expert/fast，联网开启。开发编码依赖正式需求和已有项目，当前网页只开放需求阶段。即先不提供自定义模型 ID。
- 所有任务使用独立工作目录/会话。网页不能设置任意可执行程序、shell 命令、凭据或日志目录。
- 更多设置包含单任务超时（15/30/60/120 分钟）和 Codex/WorkBuddy 的问答、工具权限策略；默认沿用现有技能的明确推荐项与本任务权限批准策略。即先问答由桌面处理。

点击“核对并发布”先查看完整任务和平台配置，点击“发布所选任务”才实际入队。这是本地有写入能力的操作入口，不是只读报告。

## 批量执行与结果

同一控制台内，后续新批次的 Mesh 和 Epsilon 各最多并发 10 条任务，Codex、WorkBuddy、即先每个平台仍为 1 条。上限跨批次共享，不是每个批次分别增加 10 个槽位。各平台可并行，每条 Mesh/Epsilon 任务使用独立的随机 session_id 和回执。

批次创建时保存 `parallelism`；升级前没有此字段的批次按原来的 1 条并发迁移，恢复旧队列不会突然扩大发送量。已占用执行槽位的任务持续观察，完成后补入排队任务；暂停不取消正在执行的任务。存在待处理交互、未知提交状态或观察错误时，暂停新增发送，同时继续观察其他已运行任务。

暂停只影响该批次尚未提交的任务，已发出的任务继续执行。未知提交状态、过期心跳、无法确认的超时会停住对应平台队列，防止继续发送造成重叠；应在原平台核验任务和连接状态，不自动重发。连接检查失败时保留具体原因，后续同平台任务保持排队。修复连接后点击“重试未发布任务”：只有原生状态仍为 prepared，且不存在发布锁、工作进程锁、回执或执行日志的失败项才重新入队；其他项不重发、不删除原始证据。

进度页显示任务状态、模型记录、已记录 Token 和工具次数。详情显示原任务、验收要求、公开回答及实验目录。缺失指标留空，执行完成不等于验收通过；批量网页本身不会自动生成模型评分。未填写验收要求时保留通用待核验项，后续可按原评价流程处理。

### 横向指标对比

执行结束后，在侧栏点击“指标对比”，或点击批次卡片上的“指标对比”。选择批次后生成冻结报告，报告顶部可切换该批次中的任务；支持独立窗口打开和下载完整指标 JSON。

当前页面、选中批次及每个批次选中的任务会写入本标签页会话存储和地址栏。浏览器刷新或点击“读取最新对比”会保留这些选择，独立报告刷新也会保留任务选择。这里只保存导航状态，尚未发布的 Excel 清单仍需在刷新后重新导入。

此页面直接复用原 `compare.py` 和 `assets/report.html`，包括总/输入/输出/缓存 Token、缓存率、工具调用错误数、任务耗时、工具调用及结果数量、工具响应均值/P95、LLM 响应均值/P95、首 Token 时间、工具明细、最终回答和评价入口。未记录的数值保持缺失，不通过字数或任务总时长推算。质量评价没有重新执行时显示待评价，不把执行结束自动计为验收通过。

报告只读取已有日志，不重新发送任务。证据未变化时复用同一冻结报告；变化时创建新的快照，保留旧报告。明确绑定同一会话的 `runs/jahead/post-completion.json` 可补充结束后到达的计费数据和最终工具事件，同时保留首次结束时间，不因刷新增加耗时。批次中的各平台可能依次启动或曾连接恢复，不能据此声称同时起跑或同模型受控实验。

每条任务对应一个标准 `experiment.json`，可继续使用既有命令：

```text
python <skill>/scripts/orchestrate.py status --experiment "详情中的实验目录"
python <skill>/scripts/orchestrate.py export --experiment "详情中的实验目录" --out "新的冻结报告目录"
```

## 可靠性与访问范围

- 批次请求 ID 和内容指纹防止双击、网络重试产生重复发布；相同 ID 内容不同则拒绝。
- 原生发布器还保留自己的独占发布锁、请求 ID 和回执；提交结果不确定不自动重试。
- 原任务正文、网页里的文字和 XLSX 单元格均按数据处理；公式、宏、外部链接不执行。
- 服务仅绑定 `127.0.0.1`，校验 Host、同源 Origin 和页面令牌；写入 API 不开放跨域访问。
- 网页进度保存在磁盘；尚未发布的导入清单只保留在当前页面，刷新后需重新导入。网络结果未确认的发布会在当前标签页会话存储中保留请求，使用“核查上次发布”复用原 ID。

## 验证

```text
python -m unittest discover -s <skill>/tests -p test_task_console.py -v
```

测试覆盖 XLSX 文本和共享字符串、多工作表、稀疏单元格、公式拦截、导入大小、任务选择、模型传递、平台并行、Mesh/Epsilon 每平台跨批次最多 10 个槽位、桌面串行队列、暂停和重启、未知状态不重发、防跨站请求，以及本地模拟 CLI 的完整执行流程。真实模型不在这些自动测试里调用。

Epsilon API 可作为第五个平台选择，独立读取 `/models`。默认示例使用本机 30100 端口，也可配置明确的内网 IP 地址，通过 SSE 跟踪；详情见 [epsilon-api.md](epsilon-api.md)。

横向指标表在同一界面固定保留 Codex、WorkBuddy、即先 AI、Mesh API、Epsilon API 五个平台列。当前任务没有执行记录的平台显示空值，不补造结果，也不触发补跑。Excel 导入、任务发布、批次进度与批次/任务切换流程沿用原入口。
